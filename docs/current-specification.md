# 現行仕様調査メモ

最終更新: 2026-06-25

## 目的

現行ソースコードから、作り直し時に引き継ぐべき仕様を整理する。

ダブルスの組み合わせ生成アルゴリズム自体は、今後 `KM0912/doubles-scheduler` を利用する前提のため、この文書では詳細な探索・採点ロジックは対象外とする。ただし、アプリ側から見た入出力、状態更新、画面挙動は記載する。

主な調査対象:

- `src/contexts/MatchContext.tsx`

## 技術構成

- アプリ種別: Create React App ベースのSPA
- 言語: TypeScript / React 18
- UI: Material UI v6
- ルーティング: 実質なし。単一画面内で下部ナビにより表示を切り替える
- 状態管理: React Context と hooks
- 永続化: `localStorage`
- デプロイ想定: README上はNetlify
- アナリティクス: 本番環境かつ `REACT_APP_GOOGLE_ANALYTICS_TRACKING_ID` 設定時のみGoogle Analyticsを初期化

## プロダクト前提

- テニスやバドミントンなどのダブルス練習会で、参加者の組み合わせと試合進行を管理するWebアプリ
- 主な利用者はサークル運営者
- 主な利用端末はスマホ。現場で片手操作しながら確認・更新する利用を中心に想定する
- 参加者は氏名ではなく通し番号で管理する
- ログイン、アカウント、サーバー保存はない
- 端末ブラウザ内の `localStorage` に保存されたデータを次回起動時に復元する

## 画面構成

画面は1ページ構成で、上部に固定ヘッダー、下部に固定ナビゲーションを持つ。スマホでの利用を主対象とし、下部ナビゲーションから片手で主要機能へ移動できる構成になっている。

下部ナビゲーションは以下の3タブ。

| タブ | 初期表示 | 主な役割 |
| --- | --- | --- |
| 試合 | Yes | 組み合わせ生成、現在の試合表示、勝敗入力、手動入替、試合終了 |
| 設定 | No | コート数、参加者管理、データリセット |
| 履歴 | No | ペア履歴、対戦履歴の確認 |

ヘッダーにはアプリ名 `ダブルス組み合わせメーカー` を表示する。

## データモデル

### Player

```ts
type Player = {
  id: number;
  gamesPlayed: number;
  wins: number;
  onBreak: boolean;
};
```

| フィールド | 意味 |
| --- | --- |
| `id` | 参加者番号。画面上では `#1` のように表示 |
| `gamesPlayed` | 完了済み試合への参加回数 |
| `wins` | 勝利数 |
| `onBreak` | 休憩中かどうか |

### Match

```ts
type Match = {
  id: number;
  team1: [Player, Player];
  team2: [Player, Player];
  winner: 1 | 2 | null;
};
```

| フィールド | 意味 |
| --- | --- |
| `id` | 試合カードのキー。現行実装では `Date.now() + index` |
| `team1` | チーム1の2名 |
| `team2` | チーム2の2名 |
| `winner` | 未入力は `null`、チーム1勝利は `1`、チーム2勝利は `2` |

### History

```ts
type History = {
  [playerId: number]: {
    [otherPlayerId: number]: number;
  };
};
```

`pairHistory` と `opponentHistory` の両方で同じ形を使う。

## 永続化

`localStorage` に保存されるキーは以下。

| キー | 内容 |
| --- | --- |
| `players` | 参加者一覧、試合数、勝利数、休憩状態 |
| `pairHistory` | ペア履歴 |
| `opponentHistory` | 対戦履歴 |

保存されない状態は以下。

- 現在生成中の試合一覧
- コート数
- 選択中の入替対象プレイヤー
- 直前ラウンドのペア・対戦情報
- 表示中タブ

起動時は `localStorage` から読み込む。該当キーがない場合は初期値を使う。JSONパース失敗時の復旧処理やスキーマバージョン管理はない。

注意点:

- 勝敗入力で更新された `wins` は `players` として保存される一方、現在の試合一覧は保存されない。そのため、勝敗入力後かつ試合終了前にリロードすると、勝利数だけが残り、対象試合は消える

## 参加者管理

### 初期状態

初期参加者は4人。

```ts
[
  { id: 1, gamesPlayed: 0, wins: 0, onBreak: false },
  { id: 2, gamesPlayed: 0, wins: 0, onBreak: false },
  { id: 3, gamesPlayed: 0, wins: 0, onBreak: false },
  { id: 4, gamesPlayed: 0, wins: 0, onBreak: false },
]
```

### 追加

- 設定タブの `参加者を追加` から追加する
- 新規IDは現在の最大ID + 1
- 追加時の `gamesPlayed`、`wins` は0、`onBreak` は `false`
- 参加者数の上限は実装されていない

### 削除

- 参加者カードの削除ボタンから削除する
- 削除前に確認ダイアログを表示する
- 試合中の参加者には休憩・削除ボタンを表示しないため、画面上は削除できない
- 削除時は `players` から対象者を消し、`pairHistory` から対象者の行・列を削除する
- 現行実装では `opponentHistory` から対象者のデータは削除していない。ただし履歴表は現在の `players` を軸に表示するため、通常画面には削除済み参加者は出ない

### 休憩

- 参加者カードの休憩ボタンから `onBreak` を切り替える
- `onBreak = true` の参加者は組み合わせ生成対象から外れる
- 試合中の参加者には休憩・削除ボタンを表示しない
- 休憩中の参加者はカード上に `休憩中` と表示される

### 表示

- 設定タブでは参加者をID昇順に表示する
- 各カードに参加者番号、試合数、勝利数、状態を表示する
- 試合中の参加者は `試合中` と表示し、カードの見た目も強調する

## コート管理

- 初期コート数は1
- 最小値は1
- 最大値は10
- 設定タブで `+` / `-` ボタンにより増減する
- 1以下では減少ボタンを無効化する
- 10以上では増加ボタンを無効化する
- コート数は `localStorage` に保存されないため、リロードすると1に戻る

## 試合生成

詳細な組み合わせ生成アルゴリズムは新実装では `KM0912/doubles-scheduler` に委譲する。

現行アプリ側の契約は以下。

- 試合タブの `試合組み合わせ生成` ボタンで生成する
- 生成済み試合がある間は生成ボタンを無効化する
- 参加者総数が4人未満の場合は生成ボタンを無効化する
- 休憩中ではない参加者だけを生成対象にする
- 生成試合数は `min(floor(参加可能人数 / 4), コート数)`
- 生成結果はコート1、コート2のように配列順で表示する
- 各試合はチーム1とチーム2を持つ
- 生成時点の勝者は未入力

注意点:

- ボタンの無効判定は参加可能人数ではなく参加者総数を見ている。そのため、参加者総数が4人以上でも休憩者が多く参加可能人数が4人未満の場合は、押下できるが試合は生成されない
- 生成中の試合は永続化されない。リロードすると消える

## 現在の試合

試合生成後、試合タブに以下を表示する。

- 見出し `現在の試合`
- コートごとの試合カード
- 各カード内に `コート N`
- `team1` の2名、`VS`、`team2` の2名
- 勝敗未入力時は `チーム1勝利` と `チーム2勝利` ボタン
- 勝敗入力後は `チームNの勝利！` と `勝敗を修正` ボタン

## 勝敗入力

### 勝者設定

- `チーム1勝利` または `チーム2勝利` を押すと、対象試合の `winner` を更新する
- 勝利チームの2名の `wins` を即時に +1 する
- 勝敗入力は試合終了処理とは別で行われる
- 画面上は勝敗入力後に勝利ボタンを隠すため、同じ試合で追加の勝者選択はできない

### 勝敗修正

- `勝敗を修正` を押すと、対象試合の `winner` を `null` に戻す
- 以前の勝利チーム2名の `wins` を -1 する
- `wins` は0未満にならないように補正する
- 無効な試合インデックスでリセットするとエラーを投げる

## 手動入替

### 試合中プレイヤー同士の入替

- 勝敗未入力のプレイヤー枠をタップすると、その枠を選択状態にする
- 別の試合中プレイヤー枠をタップすると、選択中プレイヤーとタップ先プレイヤーを入れ替える
- 入替後、選択状態を解除する
- 勝敗入力済みの試合カードではプレイヤー枠をタップできない

### 待機中プレイヤーとの入替

- 生成済み試合がある場合、`待機中の選手` を表示する
- 待機中の選手は「現在の試合に入っていない」かつ「休憩中ではない」参加者
- 試合中プレイヤーを選択中に待機中プレイヤーをタップすると、選択中の枠を待機中プレイヤーに置き換える
- 置き換えられた元プレイヤーは、結果的に待機中一覧へ戻る
- 選択中プレイヤーがない場合、待機中プレイヤーをタップしても何も起きない

## 試合終了

`試合終了` ボタンを押すと、現在生成中の全試合をまとめて完了する。

完了処理は以下。

- 現在の全試合に参加しているプレイヤーの `gamesPlayed` を +1 する
- 直前ラウンドのペア・対戦情報をメモリ上に保持する
- `pairHistory` を更新する
- `opponentHistory` を更新する
- 現在の試合一覧を空にする

仕様上の注意:

- 全試合に勝敗が入力されていなくても試合終了できる
- 試合終了の取り消し機能はない
- 勝敗入力による `wins` 更新と、試合終了による `gamesPlayed` / 履歴更新は別処理

## 履歴

履歴タブには2つのアコーディオンを表示する。どちらも初期状態で展開される。

### ペア履歴

- 見出しは `ペア履歴`
- 現在の参加者を行・列にしたマトリクスを表示する
- 同じ参加者同士のセルは `-`
- チームとして同じペアになった回数を表示する
- 履歴は双方向に記録する。例: `1-2` のペアは `pairHistory[1][2]` と `pairHistory[2][1]` の両方を +1
- 最大回数に対する比率でセル背景を濃くする

### 対戦履歴

- 見出しは `対戦履歴`
- 現在の参加者を行・列にしたマトリクスを表示する
- 同じ参加者同士のセルは `-`
- 相手チームとして対戦した回数を表示する
- 1試合につき、チーム1の各プレイヤーとチーム2の各プレイヤーの組み合わせを双方向に +1
- 最大回数に対する比率でセル背景を濃くする

## データリセット

設定タブの `リセット` ボタンで全データを初期化する。

- 押下時に確認ダイアログを表示する
- 確認すると `players` を初期4人に戻す
- `pairHistory` と `opponentHistory` を空にする
- 現在の試合一覧を空にする
- 保存済みの `localStorage` データも次回保存時に初期状態へ置き換わる

## 現行テストで確認されている挙動

主なテスト範囲は以下。

- アプリタイトル表示
- 参加者の追加、削除、リセット、休憩切替
- ペア履歴と対戦履歴の更新
- 試合生成、完了、リセット、試合中判定
- 勝敗更新と勝敗リセット
- 主要フロー: 生成、勝敗、完了、履歴更新
- 現行生成アルゴリズムの公平性確認

生成アルゴリズムのテストは、今後 `KM0912/doubles-scheduler` の責務に置き換える前提で見直し対象。

## 再実装時に判断が必要な点

- 現在の試合、コート数、表示タブを保存するか
- 参加可能人数が4人未満のとき、生成ボタンを無効化するか、明示メッセージを出すか
- 全試合の勝敗入力前に `試合終了` を許可するか
- 試合終了の取り消しを用意するか
- 参加者削除時に `opponentHistory` も削除するか
- 勝利数を勝敗ボタン押下時に即時反映するか、試合終了時に確定するか
- 氏名、レベル、性別、所属など、番号以外の参加者属性を追加するか
- PWAとしてインストール可能にするか
- サイトURL、OGP、sitemap、manifestを環境変数や設定ファイルで一元管理するか
