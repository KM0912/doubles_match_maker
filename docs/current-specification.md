# ダブルス組み合わせメーカー 再実装仕様

最終更新: 2026-06-25

## 目的

この文書は、アプリを1から再実装するための仕様を定義する。

旧ソースコードは削除済みのため、旧実装の挙動をそのまま再現することは目的にしない。旧仕様調査で確認した主要な利用体験を引き継ぎつつ、不整合が起きやすい挙動は新仕様として整理し直す。

ダブルスの組み合わせ生成アルゴリズム自体は `KM0912/doubles-scheduler` に委譲する。アプリ側では、参加者管理、試合進行、勝敗入力、履歴更新、永続化、画面操作を責務とする。

## 採用する基本方針

- 主な利用者はサークルや練習会の運営者。
- 主な利用端末はスマホ。
- ログイン、アカウント、サーバー保存は持たない。
- 参加者は番号だけで管理する。氏名、レベル、性別、所属などの属性は持たない。
- 誤操作や誤リロードに強くするため、進行中の試合を含めて `localStorage` に復元可能な状態を保存する。
- 勝敗未入力の試合があっても、ラウンド終了を許可する。
- 直前の試合終了は取り消せるようにする。
- 参加者削除時は、その参加者に関するペア履歴と対戦履歴を削除する。
- 勝敗記録は初期状態ではオフにする。オンの場合のみ勝敗入力と勝利数表示を有効にする。
- 試合数と履歴は「試合終了」時にまとめて確定する。勝敗記録がオンの場合のみ、勝利数も試合終了時に確定する。

## 推奨技術構成

- アプリ種別: SPA
- 言語: TypeScript
- UI: React
- ビルド: Vite
- ルーティング: なし。単一画面内のタブ切り替えで構成する。
- 状態管理: React state / reducer / context のいずれか。状態更新は reducer に寄せる。
- 永続化: `localStorage`
- デプロイ: 静的ホスティング

Create React App は新規採用しない。SEOやOGPは静的ファイルと設定値で管理し、URLやアプリ名を複数箇所に直書きしない。

## 画面構成

画面は1ページ構成とし、上部にヘッダー、下部にナビゲーションを置く。

下部ナビゲーションは以下の3タブ。

| タブ | 初期表示 | 主な役割 |
| --- | --- | --- |
| 試合 | Yes | 組み合わせ生成、現在の試合表示、勝敗入力、手動入替、試合終了、終了取消 |
| 設定 | No | コート数、勝敗記録、参加者管理、データリセット |
| 履歴 | No | ペア履歴、対戦履歴の確認 |

ヘッダーにはアプリ名 `ダブルス組み合わせメーカー` を表示する。

表示中タブは永続化する。リロード後は直前に開いていたタブを復元する。

### 試合タブ

試合タブは現場で最も頻繁に使う画面とし、状態に応じて表示内容を切り替える。

| 状態 | 表示内容 | 主な操作 |
| --- | --- | --- |
| 試合未生成 | 生成ボタン、参加可能人数、現在のコート数 | 組み合わせ生成 |
| 参加可能人数不足 | 生成できない理由、参加者追加または休憩解除を促す表示 | なし |
| 試合中 | 現在の試合、待機中の選手、勝敗入力、試合終了ボタン | 勝敗入力、勝敗修正、手動入替、試合終了 |
| 試合終了直後 | 次の試合生成ボタン、終了取消ボタン | 組み合わせ生成、終了取消 |
| 生成エラー | エラー内容、再試行案内 | 再生成 |

試合タブの主要アクションは `組み合わせ生成`、`試合終了`、`終了を取り消す`、`勝敗修正` とする。これらは片手操作しやすい位置とサイズで表示する。

試合中は、現在の試合カードを最優先で表示する。待機中の選手は試合カードより下に表示し、手動入替が必要なときに使える補助領域として扱う。

### 設定タブ

設定タブには、コート数、勝敗記録、参加者管理を表示する。

- コート数の変更は次回の組み合わせ生成から反映する。
- 現在の試合がある場合でもコート数は変更できる。ただし表示上は「次回から反映」と分かるようにする。
- 勝敗記録は初期状態ではオフ。オンにすると、試合タブに勝敗入力UIを表示し、設定タブに勝利数を表示する。
- 勝敗記録をオフにした場合、進行中の試合に残っている勝者情報はクリアする。
- 現在の試合に入っている参加者は、休憩と削除を操作できない。
- 休憩中、試合中、通常参加者の状態が一目で分かるように表示する。
- データリセットは設定タブの下部に置き、誤操作防止のため確認ダイアログを必須にする。

### 履歴タブ

履歴タブには、ペア履歴と対戦履歴を表示する。

- ペア履歴と対戦履歴は同じ参加者順で表示する。
- 参加者が多い場合は横スクロールできる表として表示する。
- 表の行見出しと列見出しは、スクロール中でも対応関係が分かるようにする。
- 履歴がない場合は、空の表ではなく「試合終了後に履歴が表示される」旨を表示する。

### 共通の画面状態

- 復元失敗、scheduler エラー、不正な生成結果など、ユーザー操作で回復できる問題は画面上にメッセージを表示する。
- 操作できないボタンは無効化し、必要な場合は理由を短く表示する。
- 確認ダイアログを使う操作は、試合終了、勝敗未入力を含む試合終了、終了取消、参加者削除、データリセットとする。
- スマホ画面では、下部ナビゲーションと主要アクションが重ならないように余白を確保する。

## データモデル

### Player

```ts
type PlayerId = number;

type Player = {
  id: PlayerId;
  gamesPlayed: number;
  wins: number;
  onBreak: boolean;
};
```

| フィールド | 意味 |
| --- | --- |
| `id` | 参加者番号。画面上では `#1` のように表示する |
| `gamesPlayed` | 完了済み試合への参加回数 |
| `wins` | 勝利数 |
| `onBreak` | 休憩中かどうか |

参加者情報は番号と統計値だけを保持する。

### ActiveMatch

```ts
type TeamNumber = 1 | 2;

type ActiveMatch = {
  id: string;
  courtNumber: number;
  team1: [PlayerId, PlayerId];
  team2: [PlayerId, PlayerId];
  winner: TeamNumber | null;
};
```

`ActiveMatch` は `Player` オブジェクトを直接持たず、参加者IDだけを持つ。表示時に `players` から参照する。

### ActiveRound

```ts
type ActiveRound = {
  id: string;
  createdAt: string;
  matches: ActiveMatch[];
};
```

1回の組み合わせ生成で作られた複数コート分の試合を `ActiveRound` として扱う。

### History

```ts
type History = Record<PlayerId, Record<PlayerId, number>>;
```

`pairHistory` と `opponentHistory` の両方で同じ形を使う。

履歴は現在存在する参加者だけを対象に保持する。参加者削除時は、その参加者の行と列を両方の履歴から削除する。

### UndoRecord

```ts
type UndoRecord = {
  round: ActiveRound;
  appliedPlayerDeltas: Record<PlayerId, {
    gamesPlayed: number;
    wins: number;
  }>;
  appliedPairHistoryDeltas: History;
  appliedOpponentHistoryDeltas: History;
  completedAt: string;
};
```

直前の試合終了を取り消すため、試合終了時に加算した差分を保存する。取り消し時はこの差分を逆向きに適用し、対象ラウンドを現在の試合として復元する。

### AppState

```ts
type AppState = {
  schemaVersion: 1;
  players: Player[];
  nextPlayerId: PlayerId;
  courtCount: number;
  recordWins: boolean;
  activeRound: ActiveRound | null;
  pairHistory: History;
  opponentHistory: History;
  undoRecord: UndoRecord | null;
  selectedTab: 'matches' | 'settings' | 'history';
};
```

`selectedTab` は復元するが、手動入替中の選択スロットなど一時的なUI状態は復元しない。

## 永続化

`localStorage` には単一キーで保存する。

| キー | 内容 |
| --- | --- |
| `doublesMatchMaker:appState:v1` | `AppState` 全体 |

保存対象:

- 参加者一覧
- 次に採番する参加者ID
- コート数
- 勝敗記録設定
- 現在の試合
- ペア履歴
- 対戦履歴
- 直前終了取消用の差分
- 表示中タブ

保存しない状態:

- 手動入替中の選択スロット
- ダイアログの開閉状態
- 一時的なエラーメッセージ

起動時は `localStorage` から読み込む。データが存在しない場合は初期状態を使う。JSONパース失敗、スキーマ不一致、必須フィールド欠落がある場合は、初期状態に戻し、ユーザーに復元できなかったことを表示する。

## 初期状態

初期参加者は4人。

```ts
[
  { id: 1, gamesPlayed: 0, wins: 0, onBreak: false },
  { id: 2, gamesPlayed: 0, wins: 0, onBreak: false },
  { id: 3, gamesPlayed: 0, wins: 0, onBreak: false },
  { id: 4, gamesPlayed: 0, wins: 0, onBreak: false },
]
```

その他の初期値:

| 項目 | 初期値 |
| --- | --- |
| `nextPlayerId` | `5` |
| `courtCount` | `1` |
| `recordWins` | `false` |
| `activeRound` | `null` |
| `pairHistory` | `{}` |
| `opponentHistory` | `{}` |
| `undoRecord` | `null` |
| `selectedTab` | `'matches'` |

## 参加者管理

### 追加

- 設定タブの `参加者を追加` から追加する。
- 新規IDは `nextPlayerId` を使う。
- 追加後に `nextPlayerId` を +1 する。
- 削除済みのIDは再利用しない。
- 追加時の `gamesPlayed`、`wins` は0、`onBreak` は `false`。
- 参加者数の上限は設けない。ただし画面表示は人数が増えても破綻しないようにする。

### 削除

- 参加者カードの削除ボタンから削除する。
- 削除前に確認ダイアログを表示する。
- 現在の試合に入っている参加者は削除できない。
- 削除時は `players` から対象者を削除する。
- 削除時は `pairHistory` と `opponentHistory` から対象者の行・列を削除する。
- `undoRecord` に削除対象者が含まれる場合、`undoRecord` は破棄する。

削除後に参加可能人数が4人未満になってもよい。その場合、組み合わせ生成はできない状態にする。

### 休憩

- 参加者カードの休憩ボタンから `onBreak` を切り替える。
- `onBreak = true` の参加者は組み合わせ生成対象から外れる。
- 現在の試合に入っている参加者は休憩状態を変更できない。
- 休憩中の参加者はカード上に `休憩中` と表示する。

### 表示

- 設定タブでは参加者をID昇順に表示する。
- 各カードに参加者番号、試合数、状態を表示する。
- 勝敗記録がオンの場合のみ、各カードに勝利数を表示する。
- 現在の試合に入っている参加者は `試合中` と表示し、休憩・削除操作を無効化する。

## コート管理

- 初期コート数は1。
- 最小値は1。
- 最大値は10。
- 設定タブで `+` / `-` ボタンにより増減する。
- 1以下では減少ボタンを無効化する。
- 10以上では増加ボタンを無効化する。
- コート数は永続化する。

コート数が参加可能人数に対して多い場合は、生成できる最大試合数だけを生成する。

## 試合生成

詳細な組み合わせ生成アルゴリズムは `KM0912/doubles-scheduler` に委譲する。アプリ側では scheduler を直接画面から呼ばず、アダプター関数を経由する。

アプリ側の推奨インターフェース:

```ts
type SchedulerInput = {
  playerIds: PlayerId[];
  courtCount: number;
  pairHistory: History;
  opponentHistory: History;
};

type SchedulerOutput = {
  matches: Array<{
    team1: [PlayerId, PlayerId];
    team2: [PlayerId, PlayerId];
  }>;
};
```

実際のライブラリAPIが異なる場合でも、アプリ内部では上記に近い形へ変換して扱う。

生成条件:

- 現在の試合がない場合のみ生成できる。
- 休憩中ではない参加者だけを生成対象にする。
- 参加可能人数が4人未満の場合、生成ボタンを無効化する。
- 生成試合数は `min(floor(参加可能人数 / 4), courtCount)`。
- scheduler の結果は、コート1、コート2のように配列順で表示する。
- 生成時点の勝者は `null`。
- 生成後は `activeRound` として保存する。

生成結果の検証:

- 存在しない参加者IDが含まれていないこと。
- 休憩中の参加者IDが含まれていないこと。
- 1ラウンド内で同じ参加者が複数試合に出ていないこと。
- 各チームが2人であること。
- チーム1とチーム2が同じ参加者を含まないこと。

検証に失敗した場合は試合を生成せず、エラーメッセージを表示する。

`undoRecord` が残っている状態で新しい組み合わせを生成する場合、直前終了の取り消しはできなくなる。そのため、生成前に確認するか、画面上で取り消し可能状態であることを明示する。

## 現在の試合

試合生成後、試合タブに以下を表示する。

- 見出し `現在の試合`
- コートごとの試合カード
- 各カード内に `コート N`
- `team1` の2名、`VS`、`team2` の2名
- 勝敗記録がオン、かつ勝敗未入力時は `チーム1勝利` と `チーム2勝利` ボタン
- 勝敗記録がオン、かつ勝敗入力後は `チームNの勝利` と `勝敗を修正` ボタン
- 勝敗記録がオフの場合、勝敗入力ボタン、勝者表示、勝敗未入力メッセージは表示しない
- 休憩中ではなく、現在の試合に入っていない参加者を `待機中の選手` として表示する

リロード後も `activeRound` を復元し、同じ試合カードを表示する。

## 勝敗入力

勝敗入力は、設定タブの勝敗記録がオンの場合のみ有効にする。初期状態ではオフ。

### 勝者設定

- `チーム1勝利` または `チーム2勝利` を押すと、対象試合の `winner` を更新する。
- この時点では `wins` を更新しない。
- 勝敗入力後は勝利ボタンを非表示にする。
- 勝敗入力済みの試合では、プレイヤー入替をできないようにする。

### 勝敗修正

- `勝敗を修正` を押すと、対象試合の `winner` を `null` に戻す。
- この操作では `wins` を更新しない。
- 勝敗を修正した後は、必要に応じて再度勝者を設定できる。

勝敗未入力のままでも試合終了はできる。未入力の試合は勝利数を加算しない。

勝敗記録がオフの場合、勝者設定と勝敗修正はできない。試合終了時も勝利数は加算しない。

## 手動入替

### 試合中プレイヤー同士の入替

- 勝敗未入力のプレイヤー枠をタップすると、その枠を選択状態にする。
- 別の勝敗未入力のプレイヤー枠をタップすると、選択中プレイヤーとタップ先プレイヤーを入れ替える。
- 入替後、選択状態を解除する。
- 勝敗入力済みの試合カードではプレイヤー枠をタップできない。

### 待機中プレイヤーとの入替

- 生成済み試合がある場合、`待機中の選手` を表示する。
- 待機中の選手は「現在の試合に入っていない」かつ「休憩中ではない」参加者。
- 試合中プレイヤーを選択中に待機中プレイヤーをタップすると、選択中の枠を待機中プレイヤーに置き換える。
- 置き換えられた元プレイヤーは、結果的に待機中一覧へ戻る。
- 選択中プレイヤーがない場合、待機中プレイヤーをタップしても何も起きない。

手動入替は `activeRound` に保存されるため、入替後にリロードしても反映後の組み合わせを復元する。

## 試合終了

`試合終了` ボタンを押すと、現在生成中の全試合をまとめて完了する。

終了条件:

- `activeRound` が存在すること。
- 勝敗未入力の試合があっても終了できる。
- 勝敗記録がオンで勝敗未入力の試合がある場合は、確認ダイアログで続行を確認する。

完了処理:

- 現在の全試合に参加しているプレイヤーの `gamesPlayed` を +1 する。
- 勝敗記録がオン、かつ勝者が入力されている試合では、勝利チーム2名の `wins` を +1 する。
- 全試合について `pairHistory` を更新する。
- 全試合について `opponentHistory` を更新する。
- 加算した差分を `undoRecord` に保存する。
- `activeRound` を `null` にする。
- 更新後の状態を `localStorage` に保存する。

勝敗入力による見た目の更新と、統計値の確定は分ける。統計値は試合終了時にだけ更新する。
勝敗記録がオフの場合でも、試合数、ペア履歴、対戦履歴は通常どおり更新する。

## 試合終了の取り消し

直前の試合終了は取り消せる。

表示条件:

- `activeRound` が存在しない。
- `undoRecord` が存在する。

取り消し処理:

- `undoRecord.appliedPlayerDeltas` を逆向きに適用する。
- `undoRecord.appliedPairHistoryDeltas` を逆向きに適用する。
- `undoRecord.appliedOpponentHistoryDeltas` を逆向きに適用する。
- `undoRecord.round` を `activeRound` として復元する。
- `undoRecord` を `null` にする。
- 更新後の状態を `localStorage` に保存する。

取り消し後は、終了前と同じ試合カード、チーム、勝敗入力状態を表示する。

取り消し不可になる操作:

- 新しい組み合わせ生成
- データリセット
- `undoRecord` に含まれる参加者の削除

## 履歴

履歴タブには2つのアコーディオンを表示する。どちらも初期状態で展開する。

### ペア履歴

- 見出しは `ペア履歴`。
- 現在の参加者を行・列にしたマトリクスを表示する。
- 同じ参加者同士のセルは `-`。
- チームとして同じペアになった回数を表示する。
- 履歴は双方向に記録する。例: `1-2` のペアは `pairHistory[1][2]` と `pairHistory[2][1]` の両方を +1 する。
- 最大回数に対する比率でセル背景を濃くする。

### 対戦履歴

- 見出しは `対戦履歴`。
- 現在の参加者を行・列にしたマトリクスを表示する。
- 同じ参加者同士のセルは `-`。
- 相手チームとして対戦した回数を表示する。
- 1試合につき、チーム1の各プレイヤーとチーム2の各プレイヤーの組み合わせを双方向に +1 する。
- 最大回数に対する比率でセル背景を濃くする。

参加者削除時は、削除対象者に関するペア履歴と対戦履歴を削除する。

## データリセット

設定タブの `リセット` ボタンで全データを初期化する。

- 押下時に確認ダイアログを表示する。
- 確認すると初期状態に戻す。
- 現在の試合、履歴、コート数、終了取消用データ、表示中タブも初期化する。
- `localStorage` の保存内容も初期状態へ置き換える。

サイトURL、アプリ名、説明文は設定ファイルや定数から一元管理する。Netlify、GitHub Pages、独自ドメインなどのURLを複数ファイルへ個別に直書きしない。

PWAとしてのインストール対応は初期実装では必須にしない。ただし manifest は正しいアプリ名、アイコン、テーマカラーを持つようにする。

## 旧実装から引き継がない挙動

以下は旧実装で確認されていたが、新仕様では採用しない。

- 勝敗ボタン押下時に `wins` を即時更新する挙動。
- 現在の試合を保存せず、リロードで消える挙動。

- 参加可能人数ではなく参加者総数だけで生成ボタンを有効化する挙動。
- 参加者削除時に `opponentHistory` へ削除済み参加者のデータが残る挙動。
- JSONパース失敗やスキーマ不一致を考慮しない永続化。
- `Match` が `Player` オブジェクトを直接保持する構造。

## テスト観点

### 状態更新

- 初期状態が正しいこと。
- 参加者追加で `nextPlayerId` が進み、IDが再利用されないこと。
- 参加者削除で `pairHistory` と `opponentHistory` の行・列が削除されること。
- 参加者削除時、対象者を含む `undoRecord` が破棄されること。
- コート数の最小値と最大値が守られること。

### 試合生成

- 参加可能人数が4人未満の場合、生成できないこと。
- 休憩中の参加者が scheduler に渡らないこと。
- 生成結果に重複参加者が含まれる場合、試合を作らないこと。
- 生成後に `activeRound` が保存されること。
- リロード後に現在の試合が復元されること。

### 勝敗と終了

- 勝敗入力だけでは `wins` が増えないこと。
- 勝敗修正だけでは `wins` が減らないこと。
- 勝敗記録がオンの場合、試合終了時に `gamesPlayed`、`wins`、履歴が正しく増えること。
- 勝敗記録がオフの場合、試合終了時に `gamesPlayed` と履歴だけが増え、`wins` は増えないこと。
- 勝敗未入力の試合があっても終了できること。
- 勝敗未入力の試合では `wins` が増えないこと。

### 終了取消

- 試合終了後に `undoRecord` が作られること。
- 取り消しで `gamesPlayed`、`wins`、履歴が元に戻ること。
- 取り消しで終了前の `activeRound` が復元されること。
- 取り消し後に `undoRecord` が消えること。
- リロード後でも直前の試合終了を取り消せること。

### 手動入替

- 試合中プレイヤー同士を入れ替えられること。
- 待機中プレイヤーと入れ替えられること。
- 勝敗入力済みの試合では入替できないこと。
- 入替後にリロードしても反映後の組み合わせが復元されること。

### 永続化

- `localStorage` から正常に復元できること。
- 破損したJSONを読み込んだ場合、初期状態へ戻ること。
- スキーマバージョン不一致時に安全に初期化されること。
